# 多租户 + 远程商品映射表（2026-09-16）

## 要解决的问题

商品映射表原先每个客户一份 xlsx，放在各自那台跑商家版的机器上。换一个商品就要去
那台机器上改文件，几台机器就得改几次，而且改了哪台没改哪台没人说得清。

改成：**映射表放在 web 后台维护，商家版只填一个地址**。
顺带把 web 后台做成多租户——开给某家公司用，那家公司自己登录、自己维护映射表、
自己建员工账号。

## 一个必须先知道的前提

现有的 `/dashboard` 后台**登录是假的**：cookie 里存个 `isAuthenticated=true` 就算登录
（浏览器里手写一行 `document.cookie` 就能进），而且内部 `/api/*` 完全不校验。

所以「只加一个租户控制台」并不等于把门关上——如果 `v1.leapdeer.com` 和
`admin.leapdeer.com` 指向**同一个 Next 进程**（现在就是单进程 pm2），那么从对外域名
也能打开你们自用的后台，而它是不设防的。

本次的处置（按「只把对外那半做实、现有后台不动」这个决定）：

1. **应用层**：`src/middleware.ts` 按 Host 判定。租户域名下只放行
   `/console/*`、`/api/console/*`、`/api/ys/*`、`_next/*`，其余一律 **404**
   （不是 403——403 等于承认路径存在，对扫描者是有效信息）。
2. **nginx 层**：只反代上述路径（配置见文末）。

域名清单走构建时内联的 `TENANT_HOSTS`（`next.config.js` 的 `env`，逗号分隔）。
**留空 = 不区分域名**，现有部署行为完全不变——所以这个改动可以安全地先合进去。

## 数据模型

四张新表，都在 `SqliteDatabase.init()` 里 `CREATE TABLE IF NOT EXISTS`：

| 表 | 说明 |
|---|---|
| `tenants` | 一个租户 = 一家公司。`token` 就是桌面端填的那个凭据 |
| `tenant_users` | 控制台登录账号。`role`: owner（能管账号）/ staff（只能编映射表） |
| `tenant_sessions` | 服务端会话。cookie 只是载体，真正的凭据是这一行 |
| `product_mappings` | 商品映射表，按 `tenantId` 隔离，`UNIQUE(tenantId, productId)` |

**刻意不复用** `users` / `employees`，也不给 `merchants` 加列：新体系整套独立，
现有云仓的数据和业务一行都不动。

口令哈希用 **scrypt + 每用户盐**（`scrypt$salt$hash`），不用现有的无盐 SHA-256。
现有 `users`/`employees` 保持不动——改它们会打断线上登录。

## 接口

### 机器侧（桌面端拉配置）

```
GET /api/ys/{token}            一次拿到映射表 + version
GET /api/ys/{token}/mapping    只要映射表（为以后挂别的资源留位）
```

- token 即凭据，同时接受 `Authorization: Bearer <token>`
- 令牌格式 `ys_` + 48 位十六进制；格式不对直接 404，不必查库
- 租户不存在 → 404；租户停用 → 403；两者都不回显内部信息
- 每次调用记一行访问日志（租户 + IP + UA）
- 响应里的 `version` 是映射表最后修改时间

### 控制台侧（会话 cookie，全部按 tenantId 过滤）

```
POST   /api/console/login            登录 → httpOnly 会话 cookie（30 天，滑动续期）
POST   /api/console/logout           删会话记录 + 清 cookie
GET    /api/console/me               当前用户 + 租户 + 映射表统计
GET    /api/console/mappings         分页 + 关键字（商品名/派单名/商品码/金蝶代码）
POST   /api/console/mappings         新增（商品码唯一，重复 409）
PUT    /api/console/mappings         修改
DELETE /api/console/mappings?id=     删除
POST   /api/console/mappings/import  上传 xlsx → 按商品码 upsert
GET    /api/console/mappings/export  导出 xlsx
GET    /api/console/mappings/template 空模板（表头 + 灰色示例行）
GET/POST/PUT/DELETE /api/console/users   租户员工账号（仅 owner）
```

导入是**按商品码 upsert 而不是整表替换**：运营常常只发变化的那几个商品，
整表替换会把他们没提到的商品清掉。

**重复出现的表头行会被跳过**（`isRepeatedHeader`）：客户那份商品清单第 1、2 行都是
`商品ID/商品名/金蝶代码/规格/箱规/商品大类`（手工表常见，冻结窗格/复制整行留下的），
不识别的话会导进一条商品码是「商品ID」四个字的假映射。判据是「表头里有值的每一列
都相同」才算重复——只比一列会把恰好同名的真实商品误杀。桌面端
`mapping_reader._is_repeated_header` 是同一条规则。

xlsx 的表头别名和桌面端 `app/task/mapping_reader.py` 的 `COLUMN_ALIASES`
**必须保持一致**——两边认的表头不一样，用户从后台导出的文件在桌面端就读不出来。
改一边要记得改另一边。

## 页面

`/console`（登录）、`/console/mappings`（映射表）、`/console/users`（员工账号）。

自带极简布局，不用 `DashboardLayout`——那套读的是内部后台的 localStorage 会话。

会话校验在 **`getServerSideProps`** 里做（`src/lib/console-page.ts`），不在 middleware：
middleware 跑在 Edge runtime，用不了 sqlite3，没法查会话表。middleware 只看 cookie
在不在（避免给明显没登录的人渲染出控制台外壳），真正「这个会话还有效吗」在 Node
runtime 查库确认。

## 建租户

```bash
node scripts/create-tenant.js --name "某某商贸有限公司" --contact "张三 138xxxx" \
    --username admin --password '至少8位' --display-name "张三"

node scripts/create-tenant.js --list
node scripts/create-tenant.js --disable <tenantId>      # 停用并踢掉全部会话
node scripts/create-tenant.js --enable  <tenantId>
node scripts/create-tenant.js --rotate-token <tenantId> # 旧令牌立即失效
```

`TENANT_HOST` 环境变量（默认 `https://v1.leapdeer.com`）决定打印出来的远程地址前缀。

做成了脚本而不是后台页面：开租户是低频动作，而「不动现有 dashboard」是这次的决定。

## 部署

### 环境变量

| 变量 | 说明 |
|---|---|
| `TENANT_HOSTS` | 租户域名，逗号分隔（如 `v1.leapdeer.com`）。**构建时内联**，改了要重新 build |

⚠️ **不要改 `ecosystem.config.js` 的 `BASE_URL`**：它是截图上传后拼公网图片地址用的，
WorkTool 靠它取图，改成 v1 域会让发图挂掉。

`instances: 1` 的约束继续成立（会话在 SQLite，不是进程内存，但单实例别动）。

### nginx（v1.leapdeer.com）

只反代对外那几条路径，其余直接断掉——这是第二层，第一层是应用里的 middleware：

```nginx
server {
    listen 443 ssl http2;
    server_name v1.leapdeer.com;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    # 只放行对外那半。内部后台、订单接口、上传目录、安装包一律不出去
    location ~ ^/(api/ys|api/console|console|_next)/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 20m;   # 映射表导入（接口侧也限 20MB）
    }

    location / {
        return 404;
    }
}
```

## 验证方式

这个仓库没有测试框架，验证 = `npx tsc --noEmit` + `npm run build`。
另外 `scripts/create-tenant.js --list` 能直接看数据状态。

跨项目联调：桌面端跑
`../pinduoduo_mc/.venv/bin/python ../pinduoduo_mc/tests/probe_remote_mapping.py --url <地址>`。

> **`npm run build` 和 `next dev` 不能同时跑**：两者共用 `.next/`，build 会把 dev 的产物
> 覆盖掉，dev server 立刻开始报 `Cannot find module './chunks/vendor-chunks/next.js'`
> （2026-09-16 撞了两次）。要验证构建就：先停 dev → build → `rm -rf .next` → 再起 dev。

> 注：`npm run lint` 在这个仓库不可用——`next lint` 认不出仓库里的
> `eslint.config.mjs`（flat config），会转成交互式询问。用 build 代替（它带类型检查）。
